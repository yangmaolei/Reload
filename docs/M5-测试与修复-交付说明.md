## 二、发现并修复的问题

### 🔴 P0 — 会导致数据丢失或功能完全失效

| # | 问题 | 根因 | 修复 |
|---|---|---|---|
| 1 | **多存档根同名文件导致快照创建失败** | `snapshot_files` 主键是 `(snapshot_id, rel_path_key)`，而 `rel_path_key` 不含 root_index；两个存档根下同名文件（如都有 `save.dat`）撞主键 → `UNIQUE constraint failed` → 整次快照失败 | 主键改为 `(snapshot_id, root_index, rel_path_key)`；新增 `Migrations.RebuildSnapshotFilesIfPrimaryKeyIsOld` 重建老库表（保留数据） |
| 2 | **恢复时删除用户明确排除的文件** | 快照阶段用「根级排除 + 全局排除」，恢复阶段只用「根级排除」→ 全局排除的文件（如 `*.log`）不在清单里却被当作"多余文件"删除 | RestoreService 注入 `ISettingsRepository`，删除计划与快照阶段用同一套排除规则（`LoadGlobalExcludesAsync`） |
| 3 | **引用计数回收会误删别的游戏的对象** | `SELECT hash FROM objects WHERE refcount <= 0` 是全库查询，把其他游戏遗留的零引用对象一起回收（删本地 CAS + 入队远端删除） | 限定在本次请求的 hash 集合内（`json_each` 过滤） |
| 4 | **引用计数 +2/-1 不对称** | `RegisterManyAsync` 按文件项 +1（同名同内容 +2），`DecrementReferencesAsync` 按 Distinct -1 → 计数漂移 → 对象永不回收（磁盘泄漏）或误删 | 注册端也按去重计数（每快照每 hash 只 +1），与释放端对称 |
| 5 | **恢复路径穿越** | 清单里的 `RelPath` 来自远端，`..\..\evil.dll` 会被 `Combine` 到存档根之外并写入 | Plan 阶段校验目标路径必须落在存档根内，越界条目跳过并记告警（`IsInsideRoot`） |
| 6 | **远端清单与索引的游戏不一致时快照挂错游戏** | 只校验 `SnapshotId`，没校验 `GameId` | 导入时校验 `manifest.GameId == 索引 gameId`，不一致抛 `InvalidDataException` |
| 7 | **用户点"重试上传"永远没反应** | `EnqueueAsync(forceDue)` 的 `ON CONFLICT DO UPDATE` 只重置 `next_retry_at`，不重置 `state`；而 `LeaseDueAsync` 只捞 `state='pending'` → 已 `failed` 的项永远不会被租到 | forceDue 分支同时重置 `state='pending'`、`attempts=0`、清空 `last_error` |

### 🟠 P1 — 功能异常或用户体验受损

| # | 问题 | 根因 | 修复 |
|---|---|---|---|
| 8 | **PCGamingWiki 在线查询完全失效** | 请求带了 `formatversion=2`（此时 `parse.wikitext` 是**字符串**），代码却按旧版 `{"*": "..."}` 解析 → `TryGetProperty` 抛异常被外层吞掉 → 永远返回空列表。现有测试的 fake 恰好返回旧结构，掩盖了问题 | 同时支持两种结构：字符串直接取，对象再取 `*` |
| 9 | **取消时 outbox 项永久卡在 inflight** | `catch(OperationCanceledException)` 里用**已取消的 ct** 调 `FailAsync` → 内部立刻抛 → 回写从未执行 | 改用 `CancellationToken.None` 回写 |
| 10 | **设备 ID 并发生成会分裂成多个 GUID** | `GetDeviceIdAsync` 的锁只保护缓存读，"读-判断-生成-写回"整段没串行 → 32 并发调用生成出 5 个不同 ID（索引条目分裂、多设备识别错乱） | 用 `SemaphoreSlim` 串行化整个生成流程，写回后回读确认最终值 |
| 11 | **游戏名含特定字符串时卡片渲染崩溃** | `Math.Abs(hash)` 在 hash 恰为 `int.MinValue` 时抛 `OverflowException`（已用代数法构造出触发串 `"Gycxh!"`） | 改用 `(int)((uint)hash % (uint)Backgrounds.Length)` |
| 12 | **未知主题色 seed 时界面大面积丢色** | `ThemePalettes.For` 对未知 seed 静默跳过 12 个 P/S/T 角色色，只剩 25 个中性色 | 回退到默认色板（Teal），保证恒为 37 键 |
| 13 | **桶目录创建失败后该前缀对象永久写不进去** | `EnsureBucket` 先 `_ensuredBuckets.Add()` 再 `CreateDirectory` → 创建失败后桶被永久标记为"已建" | 改为创建成功后再标记；失败可重试 |
| 14 | **服务端无 ETag 时并发发布会丢索引条目** | `canUseIfMatch=false` → 无条件 PUT 覆盖；注释声称有"内容哈希比较"但代码里没有 | 无 ETag 时写前重新读取并比对内容哈希，不一致则报 412 让上层重读重合并 |
| 15 | **WebDAV PUT 遇服务端 5xx 被当成功** | `PutAsync` 只检查 401/403，不检查响应状态 | 非成功响应抛 `WebDavException` |
| 16 | **冲突视图遇短设备 ID 崩溃** | `d.Id[..8]` 在 ID 长度 < 8 时抛 `ArgumentOutOfRangeException`（同文件另一处已用 `Math.Min` 保护） | 提取 `ShortId()` 统一处理 |
| 17 | **探测模式漏报被删除的文件** | `CompleteCore` 只遍历 `after`，探测期间被删的文件完全不可见 | 补充遍历 `before`，缺失的记为删除变更 |
| 18 | **页面切换绑定参数缺失时显示错误页面** | `PageToVisibilityConverter` 在 value 与 parameter 都为空串时判等 → 返回 Visible | 参数为空时直接返回 Collapsed |
| 19 | **用户自定义 YAML 规则整条静默失效** | `MiniYaml.TrySplitKey` 要求冒号后有空格，`namePattern:Old*` 这类写法不识别 → `ParseMapEntries` 直接 `break` → 该 map 剩余所有键被丢弃 | 放宽为"键是标识符形态且冒号后不是 `/`"时也按分隔符处理 |
| 20 | **退避"5 分钟封顶"不是硬上限** | 抖动在封顶之后应用，+20% 抖动把上限推到 6 分钟 | 封顶移到抖动之后，成为真正的硬上限 |
