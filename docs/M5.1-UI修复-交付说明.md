## 二、问题 1：海报显示异常

### 根因

原代码：

```xml
<Border CornerRadius="14" ClipToBounds="True" Visibility="{Binding HasCover, ...}">
    <Image Source="{Binding CoverPath}" Stretch="UniformToFill" />
</Border>
```

两个缺陷：

1. **`Border.CornerRadius` 不会裁剪子内容。** 已实测验证（`RenderTargetBitmap` 渲染 + 像素采样）：即使设了 `ClipToBounds="True"`，角落像素仍是子内容原色（R=255）。所以 `CornerRadius="14"` 只画了背景的圆角，`Image` 本身仍是**直角矩形**，直接压在下面的首字母色块上。
2. 没有独立的外框/底板，海报与图标层糊在一起，没有层次。

### 修复

**`Views/Pages/GamesPage.xaml`** —— 海报层改为带底板 + 描边 + 内边距的外框容器，图片自带圆角裁剪：

```xml
<Border Margin="5" CornerRadius="12"
        Background="{DynamicResource Md3.SurfaceContainerLowest}"
        BorderBrush="{DynamicResource Md3.OutlineVariant}" BorderThickness="1"
        Padding="3" Visibility="{Binding HasCover, ...}">
    <Image x:Name="CoverImage" Source="{Binding CoverPath}" Stretch="UniformToFill">
        <Image.Clip>
            <MultiBinding Converter="{StaticResource RoundedClip}">
                <Binding Path="ActualWidth"  ElementName="CoverImage" />
                <Binding Path="ActualHeight" ElementName="CoverImage" />
                <Binding Source="10" />
            </MultiBinding>
        </Image.Clip>
    </Image>
</Border>
```

**新增 `Converters/RoundedClipConverter.cs`** —— 裁剪矩形绑定图片**实际渲染尺寸**，而不是硬编码坐标。改卡片尺寸时裁剪自动跟随，不会失配。

> 为什么不用硬编码 `RectangleGeometry Rect="0,0,70,70"`：尺寸链要手工推算（88 − 2×5 边距 − 2×1 描边 − 2×3 内边距 = 70），改一处就要同步改几处，极易漏。

详情页 60×60 的海报同样处理（`DetailCoverImage`，半径 8）。

### 验证

程序化采样海报左上角轮廓（找蓝色鸭子像素的最左边界）：

```
y=252: x=344   ← 顶行偏右
y=255: x=339
y=258: x=337
y=259: x=336   ← 到底
y=263: x=336
```

逐行递减 = 圆弧轮廓。直角的话第一行就会直接到 x=336。

## 三、问题 2：窗口圆角恢复

### 根因

`MainWindow.xaml` 里 `WindowChrome.CornerRadius="0"`，根 Border 也没有 `CornerRadius`，且没有裁切 —— 整个窗口是直角。

### 修复

**`MainWindow.xaml`**：

```xml
<shell:WindowChrome.WindowChrome>
    <!-- CornerRadius 必须与根 Border 的圆角一致，否则边框和裁切会错位 -->
    <shell:WindowChrome CaptionHeight="56" ResizeBorderThickness="6"
                        CornerRadius="12" GlassFrameThickness="0"
                        UseAeroCaptionButtons="False" />
</shell:WindowChrome.WindowChrome>

<Border x:Name="RootBorder"
        Background="{DynamicResource Md3.Surface}"
        BorderBrush="{DynamicResource Md3.OutlineVariant}" BorderThickness="1"
        CornerRadius="12" ClipToBounds="True">
```

- `WindowChrome.CornerRadius` —— 系统级窗口区域裁切
- 根 Border 的 `CornerRadius` —— 内容边框描边走同一条圆弧，两者半径必须一致，否则边框画在圆外/圆内
- `ClipToBounds="True"` —— 内容（导航栏、页面）不会溢出到圆角外

**`MainWindow.xaml.cs`** —— 最大化时圆角归零（否则会在屏幕边缘露出四个缺口）：

```csharp
private const int WindowCornerRadius = 12;

private void OnStateChanged(object? sender, EventArgs e)
{
    ...
    var maximized = WindowState == WindowState.Maximized;
    MaximizeGlyph.Text = maximized ? "\uE923" : "\uE922";
    ApplyWindowCornerRadius(maximized ? 0 : WindowCornerRadius);
}

private void ApplyWindowCornerRadius(int radius)
{
    var chrome = System.Windows.Shell.WindowChrome.GetWindowChrome(this);
    if (chrome is not null) chrome.CornerRadius = new CornerRadius(radius);
    if (RootBorder is not null) RootBorder.CornerRadius = new CornerRadius(radius);
}
```

## 四、问题 3：窗口按钮悬停呈椭圆形

### 根因

`Md3.ButtonTemplate` 里圆角被**硬编码成 20**（历史原因：圆角曾用 `TemplateBinding Tag` 传递，但 `Tag` 被业务逻辑占用导致失效，于是改成写死）。

窗口按钮高 **32**，圆角 20 > 32/2 = 16 → WPF 把半径钳到边长一半 → 两端变成半圆 → 视觉上就是**椭圆/胶囊**。

### 修复（`Themes/Md3Controls.xaml`）

新增一份独立模板 `Md3.WindowButtonTemplate`，圆角写死 **6**，`Md3.WindowButton` 改用它：

```xml
<ControlTemplate x:Key="Md3.WindowButtonTemplate" TargetType="Button">
    <Grid SnapsToDevicePixels="True">
        <Border x:Name="Container" ... CornerRadius="6" />
        <Border x:Name="StateLayer" ... CornerRadius="6" Opacity="0" IsHitTestVisible="False" />
        <ContentPresenter ... />
    </Grid>
    ...
</ControlTemplate>
```

### 踩坑记录（重要）

最初尝试用**附加属性**（`Md3Assist.CornerRadius`）在模板里绑定：

```xml
CornerRadius="{Binding Path=(controls:Md3Assist.CornerRadius), RelativeSource={RelativeSource TemplatedParent}}"
```

**两种写法都失败**：

| 写法 | 结果 |
|---|---|
| `Path=(controls:Md3Assist.CornerRadius)` | 静默失败 → 回退默认值 20 → 仍是椭圆（最坑：不报错，看不出原因） |
| `Path=(clr-namespace:GameSaveSync.App.Themes.Md3Assist.CornerRadius)` | `XamlParseException`：字符串中不应有字符 "-" |
| `Path=(Reload;GameSaveSync.App.Themes.Md3Assist.CornerRadius)` | `XamlParseException`：字符串中不应有字符 ";" |

**结论：XAML 绑定路径里无法解析附加属性。** `xmlns` 别名只对元素/属性名有效，不对 `Binding Path` 生效；`clr-namespace:` 和 `程序集;命名空间` 两种前缀在 Path 里都不是合法语法。

因此最终采用**独立模板 + 写死圆角**的方案 —— 简单、可靠、零隐式行为。附加属性类 `Md3Assist.cs` 已删除。

### 验证

12 倍放大悬停态截图：左上角可见小圆弧、直边为主 —— **规整圆角矩形**，不再是两端半圆。

## 五、问题 4：扫描游戏弹窗

### 5.1 无法拖动

**根因**：`WindowStyle="None"` 的窗口没有系统标题栏，且 `WizardWindow` 没有实现任何拖拽逻辑。（`MessageWindow` 虽有，但实现是裸 `DragMove()`，会把内部按钮的点击也吃掉。）

**修复**：新增 `Services/WindowDrag.cs`，统一处理拖拽：

```csharp
public static bool TryDrag(Window window, MouseButtonEventArgs e)
{
    if (e.ChangedButton != MouseButton.Left) return false;
    // 按在交互控件上 → 交给控件自己处理（点击/选中），不拖窗口
    if (IsInteractive(e.OriginalSource as DependencyObject)) return false;
    try { window.DragMove(); return true; }
    catch (InvalidOperationException) { return false; }
}
```

`IsInteractive` 沿视觉树向上回溯，命中 `ButtonBase`/`TextBox`/`CheckBox`/`ListBox`/`ComboBox`/`ScrollBar` 等即放弃拖拽。

> C# 细节：`CheckBox`/`RadioButton` 继承自 `ToggleButton : ButtonBase`，`ListBoxItem` 继承自 `ListBox` —— 派生类必须排在基类前面，否则 `case` 不可达（CS8120）。

弹窗标题区绑定拖拽：

```xml
<Grid Grid.Row="0" Margin="28,24,18,0"
      Background="Transparent"
      MouseLeftButtonDown="Title_OnMouseLeftButtonDown">
```
```csharp
private void Title_OnMouseLeftButtonDown(object sender, MouseButtonEventArgs e) =>
    WindowDrag.TryDrag(this, e);
```

`ProbeWindow` 同步处理；`MessageWindow.Drag.cs` 改用统一助手。

### 5.2 文字渲染模糊

**根因（经实测确认）**：`AllowsTransparency="True"` 让窗口成为 **layered window**，该路径下 **WPF 关闭 ClearType 子像素抗锯齿**，文字退化为灰度抗锯齿 → 边缘发软。

量化证据（统计笔画边缘的彩色子像素占比，数值越高 ClearType 越充分）：

| 窗口方案 | 平均梯度 | 彩色边缘占比 |
|---|---|---|
| A. `AllowsTransparency=True`（原方案） | 247.6 | **9.3%** |
| B. 不透明 + `WindowChrome` 圆角 | 227.2 | **58.2%** |
| C. 完全不透明无圆角（基准） | 208.3 | 50.7% |

应用内实测同样成立：

| 位置 | 平均梯度 | 彩色占比 |
|---|---|---|
| 主窗口（无 AllowsTransparency） | 288.3 | 74.3% |
| 弹窗（修复前，layered） | 225.7 | 55.6% |
| 弹窗（修复后，WindowChrome） | 227.6 | **61.3%** |

> **过程中的判断修正**：最初怀疑是 `DropShadowEffect` 把文字渲染成离屏位图再缩放。做了对照实验（Effect 加回内容层 vs 分离），两者指标几乎一致（225.7 vs 224.4，55.6% vs 55.5%）—— **这个假设被数据否定**。真正的原因是 layered window 关闭 ClearType。

**修复**：三个弹窗统一改用 `WindowChrome` 实现圆角，不再用 `AllowsTransparency`：

```xml
WindowStyle="None" Background="{DynamicResource Md3.SurfaceContainerLow}"

<shell:WindowChrome.WindowChrome>
    <shell:WindowChrome CaptionHeight="0" ResizeBorderThickness="0"
                        CornerRadius="28" GlassFrameThickness="0"
                        UseAeroCaptionButtons="False" />
</shell:WindowChrome.WindowChrome>

<Border CornerRadius="28" Background="{DynamicResource Md3.SurfaceContainerLow}">
```

同时显式声明字体渲染参数：

```xml
TextOptions.TextFormattingMode="Ideal"
TextOptions.TextRenderingMode="ClearType"
UseLayoutRounding="True"
```

`DropShadowEffect` 一并移除 —— 圆角窗口自带 DWM 阴影，无需自绘；且 Effect 会把子树渲染成离屏位图，徒增开销。

### 验证

- **拖拽**：编写自动化脚本模拟按下→移动→抬起，弹窗位移 `dx=-144, dy=96`，与鼠标移动量完全一致 → **拖拽生效**
- **文字**：10 倍放大可见清晰的 ClearType 彩色（红/蓝/橙）子像素边缘
- **圆角**：弹窗四角为系统裁切的圆角，外观协调无白边

## 七、已知限制

1. **未覆盖 `AddGameWindow` / `ConflictWindow` / `NoteWindow` / `RelocateWindow` / `RestoreConfirmWindow`** —— 它们用的是系统默认窗口样式（非 `WindowStyle="None"`），没有 layered window 问题，本次未改动。
2. **`WindowChrome` 圆角依赖 DWM**：Windows 10 1709 以下不支持 `WindowChrome.CornerRadius` 裁切，圆角会退化为直角。目标环境为 Win10/11，无影响。
3. **DWM 阴影替代了自绘阴影**：弹窗阴影现在由系统提供，视觉参数（模糊半径、透明度）与原来的 `Md3.Elevation2` 略有差异，属正常。
4. **`RoundedClipConverter` 依赖 `ActualWidth`**：初次布局时该值为 0，转换器返回 null（不裁剪）；下一帧拿到真实尺寸后自动更新。实测无可见闪烁。
5. **海报裁剪半径为固定值 10/8**，未随图片实际尺寸等比缩放（当前尺寸固定，无影响）。
