# M10：安装版（Setup）+ v1.2.0 双版本发布

日期：2026-11-08
版本：1.2.0

---

## 一、为什么要做安装版

此前 Reload 只发布**便携版**（一个 74MB 的单文件 exe），存在三个问题：

1. **SmartScreen 每次都拦**。未签名程序没有"安装记录"，Windows 认为它是从网上下载的可疑文件，每次运行都要点"更多信息"。
2. **没有卸载入口**。用户只能手动删 exe，桌面/开始菜单快捷方式会变成死链。
3. **程序散落在任意目录**。用户从压缩包里解压到桌面就运行，`%LOCALAPPDATA%\Reload` 里的数据与程序文件分离，容易误删。

安装版解决这三点：走标准安装流程后，程序进 `Program Files`（或用户 `Programs` 目录）、注册到「应用和功能」、卸载有正规入口。

## 二、技术选型

### 为什么自研 WPF 安装器，而不是用 Inno Setup / NSIS / WiX

| 方案 | 问题 |
|---|---|
| **Inno Setup** | 经典 Windows 向导 UI，与 Reload 的 MD3 视觉完全脱节；沙箱内 UAC 提权也不稳定 |
| **NSIS** | UI 更加老旧，几乎无法定制 |
| **WiX / MSI** | MSI 的 UI 是系统固定样式，做不出品牌感；企业分发才需要 |
| **自研 WPF（采用）** | UI 完全可控，直接复用主应用的 MD3 主题 XAML，视觉统一 |

### 目标框架选 `net48` 而非 `net8.0`

安装器要跑在**「还没装 Reload、可能也没装 .NET」**的机器上。

- `net8.0` → 自包含要带 40MB+ 运行时，安装包会膨胀到 115MB
- `net48` → .NET Framework 4.8 是 Windows 10 1903+ / Windows 11 **系统自带**，安装器本身只有 800KB

### 单文件分发

安装器最终是**一个 exe**（75MB），用户下载后直接双击：

- `Reload.exe`（74MB）作为嵌入资源打进安装器 → 安装时释放到临时目录再复制
- 8 个依赖 dll（CommunityToolkit.Mvvm 及其依赖，共约 480KB）同样嵌入 → 运行时由 `AssemblyResolve` 按需释放加载
- `app.config` 的 `bindingRedirect` 规则也嵌入 → 手动解析并应用（单文件下没有外部 config）

用户选定的方案。左侧品牌色导航条（`#00696D`）+ 步骤指示器，与 Reload 主界面同一套 MD3 主题。

```
┌──────────────┬────────────────────────────────┐
│  R  Reload   │  欢迎使用 Reload                │
│  游戏存档同步 │                                │
│              │  游戏存档备份与多设备同步工具…   │
│ ● 欢迎       │  ┌──────────────────────────┐   │

│ ○ 安装范围   │  │ 安装器会复制程序文件…     │   │
│ ○ 安装位置   │  └──────────────────────────┘   │
│ ○ 安装选项   │                                │
│ ○ 正在安装   │                    [上一步][下一步]│
│ ○ 完成       │  [取消]                         │
```

六个步骤：

1. **欢迎** —— 说明安装器会做什么、强调「卸载不会删存档数据」
2. **安装范围** —— 仅当前用户（免 UAC）/ 所有用户（装到 Program Files）
3. **安装位置** —— 可自定义，带合法性校验（拒绝盘根目录）
4. **安装选项** —— 桌面与开始菜单快捷方式、开机自启
5. **正在安装** —— 实时步骤清单
6. **完成** —— 显示安装结果路径

## 四、实现结构

新建项目 `src/GameSaveSync.Setup/`：

| 文件 | 职责 |
|---|---|
| `InstallPlan.cs` | 安装计划（范围、目录、快捷方式、自启）+ 路径规划与校验 |
| `Installer.cs` | 执行器：建目录、复制文件、建快捷方式、注册卸载项、写自启；含卸载逻辑 |
| `Shortcut.cs` | 创建 .lnk 快捷方式 |
| `UninstallLocator.cs` | 从注册表反查安装目录（卸载时用） |
| `SetupArguments.cs` | 提权重启时传递用户选择 |
| `SetupViewModel.cs` | 向导状态机（可单测，不依赖 WPF 渲染） |
| `Converters.cs` | 步骤 → Visibility、Scope → bool 等 |
| `EmbeddedAssemblyLoader.cs` | 依赖 dll 与绑定重定向的按需加载 |
| `Polyfills.cs` | net48 缺失的 `IsExternalInit` / `required` 等 |

新建测试项目 `tests/GameSaveSync.Setup.Tests/`（net48，36 条用例）。

### 关键设计

- **默认不提权**。安装器 manifest 是 `asInvoker`，只有用户明确选「所有用户」时才通过 `ShellExecute runas` 自提权重启。选「仅当前用户」的用户**根本不会看到 UAC 弹窗**。
- **卸载是安装器自己**。`UninstallString` 指向 `Reload-Setup.exe --uninstall`，不额外生成卸载器 exe。
- **业务逻辑与 UI 分离**。`SetupViewModel` 是纯状态机，可脱离 WPF 单测。

## 五、修掉的两个真实 Bug

### 1. 快捷方式静默生成失败

最初用 COM 的 `IShellLink` + `IPersistFile` 创建快捷方式。**不抛异常、文件也不生成**——因为 vtable 声明顺序稍有偏差，`Save` 就落到了错误的槽位。

尝试过手写 .lnk 二进制格式（Shell Link Binary File Format），字段偏移算错，Windows 解析不出来。

**最终方案**：`WScript.Shell` 的 `CreateShortcut`。它是后期绑定的 IDispatch 接口，没有 vtable 顺序问题。

> 附带坑：COM 的 IDispatch 成员**不能用 `GetMethod` / `GetProperty` 拿**（反射看不到），必须用 `Type.InvokeMember` 走后期绑定。

### 2. 卸载注册表项没删掉

用了 `key.DeleteValue(null)` —— 那是删**默认值**，不是删子键。结果文件全删了，但「应用和功能」里 Reload 还在。

**修正**：`baseKey.DeleteSubKeyTree(path)`。

已加回归测试锁定（`Install_ThenUninstall_RemovesUninstallRegistryKey`）。

### 真机端到端

**安装 → 卸载全流程**：

```
after install:   {'install_dir': True, 'exe': True,
                  'desktop_lnk': True, 'startmenu_lnk': True}
after uninstall: {'install_dir': False, 'exe': False,
                  'desktop_lnk': False, 'startmenu_lnk': False}
```

- 安装后系统状态：程序目录 ✅ exe ✅ 桌面快捷方式 ✅ 开始菜单快捷方式 ✅ 卸载注册表项 ✅
- 卸载后系统状态：以上全部清除 ✅
- 「应用和功能」中的卸载项：安装后存在、卸载后消失 ✅

**单文件独立性**：把 `Reload-Setup.exe` 单独放进一个**空目录**（无任何 dll、无 config）运行：

```
✓ 窗口出现，说明依赖 dll 从嵌入资源加载成功
程序文件已安装: True
桌面快捷方式: True
开始菜单快捷方式: True
文件大小: 74001203
```

### 未覆盖

- 「所有用户」安装的 UAC 提权路径**未真机验证**（沙箱内无法稳定完成提权交互），逻辑上有单元测试覆盖分支，实际提权交互需人工确认。
- 升级安装（覆盖旧版本）未做专项测试。
